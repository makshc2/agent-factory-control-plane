# Proposal: add-factory-board

## Why

Оператор agent-orchestrator-kit веде кілька репозиторіїв зі spec-driven пайплайном OpenSpec і сьогодні змушений вручну відкривати кожен репозиторій, щоб зрозуміти стан активних змін (фаза, прогрес задач, вердикт рев'ю, блокери). Це не масштабується вже на 3–5 проєктів. Потрібен єдиний борд, який автоматично збирає OpenSpec-артефакти з віддалених репозиторіїв GitHub і GitLab та показує їх в одній таблиці.

## What Changes

- Додається реєстр відстежуваних віддалених проєктів (провайдер GitHub/GitLab, репозиторій, гілка, опційний токен) із збереженням у localStorage — без власного бекенда.
- Додаються API-клієнти для GitHub REST v3 та GitLab REST v4 на базі Axios: перелік тек `openspec/changes/<name>/` і читання `handoff.md`, `tasks.md`, `review.md` з токен-авторизацією з env (`VITE_*`) або з налаштувань проєкту.
- Додається нормалізована модель стану зміни: фаза/next_command із `handoff.md`, прогрес задач n/m із `tasks.md`, вердикт із `review.md`, ознака blocked.
- Додається полер, що періодично (та за ручним запитом) оновлює дані всіх проєктів реєстру; помилки (401/403/404/rate limit) фіксуються per-project і не валять застосунок.
- `BoardView` перетворюється з заглушки на таблицю: один рядок = одна активна зміна проєкту; колонки — проєкт, зміна, фаза/next_command, прогрес задач, вердикт рев'ю, оновлено, blocked/помилка.
- Дизайн-бриф: none — UI є звичайною Vue-таблицею, `require_design_brief: false`.

## Non-goals

- Власний бекенд або проксі-сервер — борд працює виключно з браузера напряму з API GitHub/GitLab.
- Запис у віддалені репозиторії — борд строго read-only, жодних мутацій артефактів.
- Пагінація понад `per_page=100` — зафіксоване обмеження v1 (див. decisions.md).
- ETag-кешування відповідей API — відкладено на v1.1.
- Багатокористувацький режим і серверне зберігання токенів — токени в localStorage прийнятні лише для single-operator із read-only токенами.

## Capabilities

### New Capabilities

- `project-registry`: реєстр віддалених проєктів — додавання, редагування, видалення записів (провайдер, repo, гілка, токен) і персистенція у localStorage.
- `artifact-ingestion`: отримання OpenSpec-артефактів активних змін через GitHub/GitLab REST API та парсинг у нормалізовану модель стану зміни.
- `board-polling`: періодичне й ручне оновлення даних усіх проєктів реєстру з ізоляцією помилок per-project.
- `factory-board`: таблиця борду в `BoardView` — рядки активних змін, колонки стану, порожній стан і індикація помилок по рядках.

### Modified Capabilities

Немає — `openspec/specs/` порожній, усі вимоги нові (ADDED).

## Acceptance criteria

- Реєстр проєктів зберігається у localStorage під ключем `factory-board.projects.v1` і переживає перезавантаження сторінки.
- Борд показує рядок на кожну активну зміну кожного проєкту реєстру: фаза/next_command, прогрес задач n/m, вердикт рев'ю та час останнього оновлення.
- Помилка одного проєкту (auth / rate-limit / not-found / network) показується в його рядку і не валить борд та інші проєкти.
- Полінг виконується за інтервалом з `VITE_POLL_INTERVAL_MS` (за замовчуванням 60 с); ручне оновлення доступне з UI.
- `npm run lint`, `npm test` та `npm run build` завершуються без помилок.

## Impact

- Код: `src/api/` (нові клієнти провайдерів), нові `src/stores/`, нові `src/components/`, нові `src/utils/` (парсери), `src/views/BoardView.vue`, `src/styles.css`, `.env.example`.
- Залежності: нові npm-пакети не потрібні — Vue 3, Pinia, Vue Router, Axios вже в проєкті.
- Зовнішні API: GitHub REST v3 та GitLab REST v4, лише читання (contents/tree/files).
- Безпека: токени зберігаються в env-файлах оператора або в localStorage браузера; прийнятно для single-operator v1, не для командного використання.
